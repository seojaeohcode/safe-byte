# Safe-Byte Ncloud Terraform

This folder provisions the minimum NAVER Cloud infrastructure for the Dockerized Safe-Byte MVP:

- VPC
- public subnet
- ACG firewall rules for SSH and HTTP from trusted CIDRs only
- network interface
- login key
- Ubuntu server
- public IP
- init script that installs Docker and creates a `deploy` user

Terraform creates infrastructure. The app itself is shipped with `scripts/provision_and_deploy.ps1`, which syncs this repository to the instance and runs Docker Compose.

## 1. Prepare credentials

Prefer environment variables so credentials do not land in Terraform files:

```bash
export NCLOUD_ACCESS_KEY="..."
export NCLOUD_SECRET_KEY="..."
export NCLOUD_REGION="KR"
```

The Ncloud provider supports the `NCLOUD_ACCESS_KEY`, `NCLOUD_SECRET_KEY`, and `NCLOUD_REGION` environment variables.

On this Windows workspace, you can also fill the ignored local file:

```text
infra/terraform/.env.ncloud
```

Then run Terraform through the wrapper:

```powershell
.\infra\terraform\scripts\tf.ps1 plan
.\infra\terraform\scripts\tf.ps1 apply
```

## 2. Configure variables

```bash
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars
```

Edit:

- `admin_ssh_public_key`
- `ssh_allowed_cidr`
- `login_key_name` only if you do not want the default `safebyte-tf-key`

Use your public IP with `/32` for `ssh_allowed_cidr` and `web_allowed_cidr` once the demo is stable.

By default this template creates an Ncloud Login Key with Terraform:

```hcl
create_login_key = true
login_key_name   = "safebyte-tf-key"
```

The Ncloud provider stores generated login-key private material in Terraform state. Treat `terraform.tfstate` as a secret. If you later find an existing Login Key, switch to:

```hcl
create_login_key = false
login_key_name   = "EXISTING_LOGIN_KEY_NAME"
```

## 3. Provision infrastructure

```bash
terraform init
terraform plan
terraform apply
terraform output
```

Or on this Windows workspace:

```powershell
.\infra\terraform\scripts\tf.ps1 init
.\infra\terraform\scripts\tf.ps1 plan
.\infra\terraform\scripts\tf.ps1 apply
```

Or provision and deploy in one flow:

```powershell
.\infra\terraform\scripts\provision_and_deploy.ps1
```

That command creates the low-cost `mi1-g3` server with `fee_system_type_code = "FXSUM"`, uploads the current project over SSH, runs Docker Compose, and updates `web/config.js` to call the remote backend.

## 4. Deploy the app

The secure Windows deployment script refreshes `config/ncloud_cost_snapshot.json` from the local Billing API credentials, builds a temporary deployment package, copies the local sample folder into `data/selected_ocr_samples`, removes `NCLOUD_*` values from the app `.env`, forces `HTTP_PORT=80` if missing, and then runs:

```bash
docker compose up -d --build
```

Open the output URL:

```bash
terraform -chdir=infra/terraform output app_url
```

To point the local frontend at the new server:

```powershell
.\scripts\set_frontend_api.ps1
cd web
python -m http.server 5173
```

Open `http://127.0.0.1:5173/index.html`.

The deployed Compose stack includes an internal Redis container for hot OCR cache reads. It does not create Cloud DB for Cache or any other managed cache resource.

## Notes

- Keep `.env`, `infra/terraform/.env.ncloud`, `terraform.tfvars`, and `*.tfstate` private.
- Terraform state can contain sensitive infrastructure metadata.
- Ncloud login keys place private key material in state when generated by Terraform.
- Do not put `NCLOUD_ACCESS_KEY` or `NCLOUD_SECRET_KEY` in the app `.env`; use `infra/terraform/.env.ncloud` for Terraform.
- Do not expose port `8000`; only unprivileged Nginx on host port `80` should be public, and only from `web_allowed_cidr`.
- The cost panel uses a deployment-time Billing API snapshot, so just-created resources can appear as `0` until Ncloud billing data catches up.
